App Store 上架操作手冊

粵.fun 專用的逐步操作指引 —— 含 2026 年最新強制要求、沒有 Mac 的完整替代方案，以及最可能被拒的一環怎麼答。

$99／年 個人帳號 無封測門檻 需 Xcode 26 ⚠️ 要有 Apple 裝置 海外首發

〇、先看時間預期

好消息：Apple 沒有 Google Play 那道 12 人 × 14 天的封測門檻。 App Store 首次送審一般 1–3 天出結果（偶有拖到一週）。所以純技術流程比 Google Play 快得多 —— 從帳號開通到上線，樂觀情況一週內可完成。
壞消息：有一道 Google Play 沒有的硬門檻 —— 你必須有一台 Apple 裝置。 中國大陸的個人開發者，Apple 要求用 Apple Developer App 完成註冊與身分驗證， 而該 App 只跑在 iPhone／iPad／Mac 上，且整個註冊流程不能換裝置。 更關鍵的是：沒有 Mac 也沒有 iPhone／iPad，你連測試都沒法測 —— iOS 模擬器只存在於 macOS，而 TestFlight 只能裝在 iOS/iPadOS 上。 這件事必須先解決，其餘步驟才有意義。

一、前置：先解決「Apple 裝置」這件事

這是本手冊唯一需要你花錢或借東西的地方，而且無法用技術繞過。三種情況對應三條路：

你的情況能不能上架怎麼做
有 iPhone 或 iPad✓ 可以最順。用它完成註冊與身分驗證（Apple Developer App 支援 iPhone／iPad），之後也用它裝 TestFlight 實測。Mac 不是必需的。
沒有 Mac 也沒有 iPhone／iPad✗ 目前不行兩條路：① 借一台 iPhone（註冊期間別換裝置）；② 走官方替代驗證 —— 官方文件寫明「如需使用 Apple Developer App 以外的方式驗證身分，請聯繫支持團隊」。但即使註冊成功，你仍無法測試 iOS 版，建議至少弄一台二手 iPhone。
有 Mac✓ 可以用 Mac 上的 Apple Developer App 註冊，順便還能本機跑 Xcode 與模擬器。
「註冊期間不能換裝置」不是嚇唬人。 官方流程明確要求「你必須在整個註冊流程中使用相同的裝置」。 實際案例中，開發者因為中途換手機、或街道地址填得太簡略，被系統判為 Action not allowed，帳號註冊無法完成且難以救回。 街道地址請照身分證上的地址逐字填。

二、註冊 Apple Developer Program（逐步）

1

準備 Apple ID 並開啟雙重認證

若沿用日常 Apple ID，先在 iPhone／iPad 的「設定 → 你的名字 → 密碼與安全性」確認「雙重認證」已開啟。開發者帳號強制要求。

2

在 Apple Developer App 中註冊（不是網頁）

於裝置上安裝 Apple Developer App → 「帳戶」分頁 → 登入 Apple ID → 「現在註冊」。

3

填個人資料 + 拍自拍照

輸入法定姓名、身分證號、電話。姓名必須與身分證一致；地址填身分證上的地址。系統會要求拍一張自拍照做身分比對。

4

選 Individual（個人）實體類型並付費

組織類型要 D-U-N-S 編碼，你不需要。付 ¥688／年，個人帳號可用微信或支付寶。

5

留意補件郵件

付費不等於成功。常見情況是隔天收到郵件要求上傳身分證正反面，透過郵件裡的連結上傳即可。審核約 1–3 個工作日。

6

記下 Team ID

帳號開通後，於 developer.apple.com/account → Membership 頁找到 Team ID（10 碼英數），後面設定 CI 要用。

三個會讓註冊卡死的地雷 ① 中途換裝置 —— 直接判定帳號異常，且客服無權重設；
② 姓名填暱稱／公司名 —— 審核延誤或退回；
③ 地址填郵政信箱或隨手寫 —— 官方明確不接受郵政信箱，實務上會被要求改成身分證地址。
遇到任何錯誤，不要在 App 內反覆重試，直接聯繫 Apple 支持。

四、簽名憑證：沒有 Mac 也辦得到

憑證申請傳統上要 Mac 的「鑰匙串存取」，但實際上用 openssl 在 Windows 上就能完成 —— Apple 只要求你提交一個標準的 CSR。全部三樣東西如下：

要申請的東西在哪申請用途
Apple Distribution 憑證（.cer → .p12）developer portal → Certificates簽署 App 本體
Provisioning Profile（.mobileprovision）developer portal → Profiles授權這個 App 可上架 App Store
App Store Connect API Key（.p8）App Store Connect → Users and Access → Integrations讓 CI 能上傳 build

4.1 在 Windows 上產生 CSR 與 .p12

Git Bash 已內建 openssl。把 你的@信箱、你的名字 換掉即可：

# 1) 產生私鑰
openssl genrsa -out ios_dist.key 2048

# 2) 產生 CSR（上傳到 Apple）
openssl req -new -key ios_dist.key -out ios_dist.certSigningRequest \
  -subj "/emailAddress=你的@信箱/CN=你的名字/C=CN"

# 3) 到 developer portal → Certificates → + → Apple Distribution
#    → 上傳上面的 .certSigningRequest → 下載 distribution.cer

# 4) 把 .cer（DER）轉成 PEM，再與私鑰合成 .p12
openssl x509 -inform DER -in distribution.cer -out distribution.pem
openssl pkcs12 -export -inkey ios_dist.key -in distribution.pem \
  -out cert.p12 -name "Apple Distribution"
#    過程中會要你設一組匯出密碼 —— 記住它，等下要填進 GitHub Secrets
ios_dist.key 是你的命根子 和 Android 的 upload-keystore.jks 同等地位：遺失後該憑證無法再用（只能撤銷重簽，舊 build 的簽章關係也一併失效）。 請與 cert.p12 一起離線備份兩份以上，密碼分開存放。

4.2 申請 Provisioning Profile

  1. developer portal → Profiles → +
  2. 選 App Store Connect（分散式）類型
  3. App ID 選 com.jyutfun.app
  4. 憑證勾選上一步申請的 Apple Distribution
  5. 命名（例如 JyutFun App Store）→ 下載 .mobileprovision

這個名稱要原封不動填進 GitHub Secrets 的 IOS_PROVISION_NAME。

4.3 申請 App Store Connect API Key

  1. App Store Connect → 使用者與存取權 → Integrations → App Store Connect API
  2. 角色選 App Manager（或 Admin）
  3. 產生後立刻下載 .p8 —— 只能下載一次，關掉就再也拿不到
  4. 同時記下 Key ID 與頁面上方的 Issuer ID

五、上傳 build：你不需要 Mac

iOS 打包本來必須在 macOS + Xcode 上做，這台機器不行 —— 但把打包搬到雲端就解決了。倉庫裡已備好 .github/workflows/ios.yml，跑在 GitHub 的 macos-26 runner 上（Apple M4、Xcode 26）。

第一次先不要配 Secrets，跑一次「無簽名編譯驗證」 工作流在沒有憑證時會自動降級為 CODE_SIGNING_ALLOWED=NO 的 archive， 目的只有一個：證明這個 iOS 工程真的編得過。工程有問題會在這裡就報錯，不必等到簽名階段才發現。 綠燈之後再逐一補 Secrets。

5.2 觸發方式

  • 推 tag：git tag v1.0 && git push origin v1.0 —— 自動打包、校驗、上傳 TestFlight
  • 手動：Actions → iOS Build → Run workflow，勾選 upload 才會上傳

5.3 工作流在你背後做了什麼

  1. 顯式選用 Xcode 26 並斷言主版本 ≥ 26（低於 26 直接失敗，因為上傳必被拒）
  2. 確認 ios/ 工程存在（缺失就報錯並提示跑 tools/ios_setup.py）
  3. npx cap sync ios 同步 web 資源並跑 pod install，然後確認三個必要輸入檔都在
  4. 比對音檔數（源 app/ vs 同步後）—— 這道防線是為 Android 那次事故加的：同步被截斷卻照樣建置成功，包能裝能開但沒聲音
  5. 斷言 ITSAppUsesNonExemptEncryption=false 與隱私清單已進資源清單
  6. archive → 匯出 IPA → 用 verify_bundle.py 跑引用閉環校驗（與 Android 共用同一套）
  7. 上傳 TestFlight，並等 Apple 處理完畢
build number 不會撞號 工作流用 github.run_number 當 CURRENT_PROJECT_VERSION，每次執行天然遞增。 App Store Connect 要求每次上傳的 build number 必須比之前大，這一項自動滿足。

八、最大的審核風險：Guideline 4.2

WebView 包裝型 App 最常死在這一條。 App Review Guideline 4.2「最低功能要求」原文要求 App 「應包含足以超越『重新包裝的網站』的功能、內容與介面」。 審查員的實際做法是：打開你的 App、再打開你的網站，找「App 做得到、瀏覽器做不到的事」。 如果答案是「沒有」，就駁回。

8.3 如果真的被 4.2 駁回

  • 不要原封不動重投，也不要在 Resolution Center 純粹辯論 —— 重複提交近似版本會招來 4.3「垃圾 App」判定，那比 4.2 更難翻身。
  • 在 Resolution Center 回覆，並附上一段螢幕錄影：開飛航模式 → 開 App → 逐字點讀有聲 → 整句朗讀 → 顯示進度保存。
  • 若要再加保險，可補上真正的原生能力：原生分享、觸覺回饋、原生啟動畫面動畫等。但先試 8.2 的備註 + 錄影，本 App 的材料通常足夠。

九、中國大陸區的特別限制

不要選中國大陸作為發行地區 —— 會需要 ICP 備案號。 App Store 中國區自 2023 年起要求 App 提供工信部 ICP 備案號，而你沒有營業執照， 無法辦理。因此發行地區只勾選海外（香港、台灣、新加坡、馬來西亞、美加等粵語社群）。 香港、中國台灣等地區同樣有大量粵語學習需求，首發受眾完全夠。
