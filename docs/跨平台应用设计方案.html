一、项目概述与内容资产盘点

本项目目标是把现有《粵語（香港話）教程（修訂版）》内容产品化为一个移动学习应用，覆盖 iOS 与 Android 双平台。当前工作区已具备的内容资产：

  • 教材正文：《粵語（香港話）教程（修訂版）》PDF 一册，含 30 课内容（第 0 课为语音入门，第 1–29 课为正课）。
  • 配套音频：138 个 MP3 文件，按 章节-课号.mp3 命名（如 1-1.mp3、25-3.mp3），与教材章节一一对应。

据此确定产品核心形态：「课程文本 + 音频跟听」的离线优先型语言学习 App。核心用户旅程：选课 → 看课文/对照音频 → 逐句跟听跟读 → 记录生词 → 追踪学习进度。

二、技术选型

方案优势劣势结论
Flutter 推荐 单代码库双端；UI 一致性高；just_audio + audio_service 组合对后台播放、锁屏媒体卡片、倍速支持成熟；渲染性能好，长列表流畅 包体略大（+6–8MB）；平台深定制需写通道代码 采纳
React Native 备选 团队若以 Web/JS 为主可复用技术栈；react-native-track-player 可用 音频后台播放原生模块维护成本高；UI 一致性需额外投入 备选
双端原生（Swift + Kotlin）平台体验极致两套代码两倍成本，本项目无重度平台特性需求，性价比低不采纳
选型理由：本项目是典型的「内容 + 音频」应用，无 AR、无重度传感器、无复杂原生 UI 需求，Flutter 的音频生态（just_audio / audio_service / record）已完全覆盖需求，一套代码可显著降低双端成本约 40%。

三、总体架构

采用分层架构 + 离线优先（Offline-First）设计，分为三层：

  • 界面层：课程首页、课文页、播放器页、生词本、我的（设置/进度统计）。
  • 业务层：课程进度管理、播放队列编排、下载任务调度、复习提醒策略。
  • 数据层：Isar 数据库（课程/进度/生词）、CDN 音频源、本地音频缓存目录。

内容分发采用「瘦包体 + 按需加载」：138 个 MP3（估算总量 150–300MB）不打包进安装包，启动时拉取课程清单 JSON，音频按课流式播放并缓存，用户可手动「下载整课」离线使用。安装包预计 < 30MB。

四、关键平台差异与实现要点

iOS

  • Info.plist 开启 Background Modes → Audio，否则退后台即断音。
  • AVAudioSession 类别设为 playback；just_audio_background 已自动处理。
  • 锁屏控制中心（MPNowPlayingInfoCenter）由 audio_service 桥接，显示课名/进度/倍速。
  • 麦克风权限（跟读功能）需 NSMicrophoneUsageDescription 文案。

Android

  • 音频播放走前台服务（Foreground Service, type mediaPlayback），Android 14+ 需声明 FOREGROUND_SERVICE_MEDIA_PLAYBACK 权限。
  • MediaSession 对接通知栏媒体卡片与蓝牙耳机按键。
  • 音频焦点（Audio Focus）：来电/其他 App 播放时自动暂停并恢复。
  • Android 13+ 通知权限需运行时请求。

八、音频编号关联机制（点读功能）

教材排版中大量出现耳机图标 + 音轨编号（如「粵語常用字表 0-2」、二维码旁的音频入口）。阅读时用户需要点击编号直接听到对应音频，为此设计如下关联链路：

教材音轨编号            内容整理               App 运行时
┌──────────┐   正则扫描/人工标注   ┌──────────────┐   点击徽章    ┌─────────────┐
│ 「0-2」  │ ─────────────────→ │ lessons.json │ ──────────→ │ AudioBadge  │
│ 耳机图标 │   生成结构化标记     │ key ↔ 文件映射│  key 查找    │ 点击即播     │
└──────────┘                    └──────────────┘             └─────────────┘
                                  映射规则：key = "{章}-[{节}" → audio/{key}.mp3

1. 映射规则与清单

  • 音轨编号与文件名天然一一对应：编号 0-2 ↔ 粵語教程/0-2.mp3（已验证：138 段音频、31 个章节，扫描脚本见 prototype/lessons.json）。
  • 内容整理阶段用正则 ^(\d+)-(\d+)\.mp3$ 扫描音频目录生成 lessons.json（含 chapter / audioKey / 文件大小），正文整理时把教材中的编号替换为内联标记 <audio-ref key="0-2"/>。
  • 未匹配到的编号（编号存在但音频缺失）在构建期校验报错，避免线上出现「哑图标」。

2. Flutter 端实现：AudioBadge 组件

/// 内联音频徽章：点击即通过全局播放器播放对应音轨
class AudioBadge extends ConsumerWidget {
  final String audioKey;                       // 如 "0-2"
  const AudioBadge({super.key, required this.audioKey});

  @override
  Widget build(BuildContext context, WidgetRef ref) {
    final player = ref.watch(playerControllerProvider);
    final isCurrent = player.currentKey == audioKey && player.isPlaying;
    return InkWell(
      borderRadius: BorderRadius.circular(999),
      onTap: () => ref.read(playerControllerProvider.notifier)
          .toggleTrack(audioKey),          // 播放/暂停切换，复用全局播放器
      child: Container(
        padding: const EdgeInsets.symmetric(horizontal: 10, vertical: 2),
        decoration: BoxDecoration(
          border: Border.all(color: const Color(0xFFC0392B), width: 1.5),
          color: isCurrent ? const Color(0xFFC0392B) : Colors.white,
          borderRadius: BorderRadius.circular(999),
        ),
        child: Row(mainAxisSize: MainAxisSize.min, children: [
          Icon(Icons.headphones, size: 14,
              color: isCurrent ? Colors.white : const Color(0xFFC0392B)),
          const SizedBox(width: 4),
          Text(audioKey, style: TextStyle(fontSize: 13, fontWeight: FontWeight.w600,
              color: isCurrent ? Colors.white : const Color(0xFFC0392B))),
          if (isCurrent) ...[
            const SizedBox(width: 4),
            const EqIndicator(),           // 播放中音波动画
          ],
        ]),
      ),
    );
  }
}

3. 播放策略

  • 点击徽章 → key 查 lessons.json 得到音频 URL（CDN 路径 audio/0-2.mp3）→ 交给全局 just_audio 播放器（页内小图标不单独出声，统一进底部迷你播放器，支持倍速/循环/锁屏控制）。
  • 同一课内点击编号自动连播队列：点 0-2 后播完自动接 0-3（若存在）。
  • 正文 HTML 用 flutter_widget_from_html 渲染，自定义标签 <audio-ref> 映射为 AudioBadge，无需为每课手写 UI。
