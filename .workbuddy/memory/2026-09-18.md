## 【解決「未安裝粵語音色」問題】本地字庫 + 四層發音路由

- **問題根因**：點讀走 Web Speech API，裝置無粵語音色時 `speak()` 直接 return + 彈提示，功能完全失效（Android / 多數桌面瀏覽器都無裝）。
- **解法**：把「發音」從系統依賴改成**自帶資產**。新增 `tools/gen_char_audio.py`，用 edge-tts（zh-HK-HiuMaanNeural, rate −20%）為課程全部漢字預生成單字 MP3 → `app/audio/chars/`（1105 檔 / 11.8MB）+ 索引 `app/content/char_audio.json`（62KB，`{字: {d:預設檔, r:{粵拼:檔}}}`）。
- **多音字關鍵技巧（同音字替身法）**：單字 MP3 讀音由 edge-tts 決定，多音字（行/重/長/中）無法控制。做法是找一個**只讀該音節的常用同音字**去合成，檔名仍以原字+粵拼命名。例：`行 hong4 → 借「杭」出聲`、`重 zung6 → 「仲」`、`咁 gam2 → 「感」`、`假 gaa2 → 「價」`、`姐 ze1 → 「遮」`、`平 peng4 → 「坪」`、`為 wai4 → 「惟」`。共 15 個替身，全部音準正確。
  - 常用字判定用 **GB2312 一級字庫**（`char.encode('gb2312')` 首字節 0xB0–0xD7），避免挑到 edge-tts 讀不出的生僻字。
  - **大坑**：替換條件必須是「課程讀音 ≠ 字典首選讀音（`get_jyutping_candidates(c)[0][1][0]`）」，若只寫 `len(cands)>1`（粵語幾乎每個字都有變調候選）會誤替 362 個字，並產生「達→帝」這類錯音。加上這個條件後降到 15 個，全部正確。
  - 課程漢字↔粵拼對齊：把 `y` 的漢字序列同 `p` 的音節序列逐位配對（565 字有讀音，錯位 0 句）。
- **前端四層發音路由**（`app/index.html`，取代原 `speak()`）：
  1. **課程原聲**：`TEXT2CLIP[normKey(原文)]` 命中就直接播既有錄音（最自然）
  2. **本地單字音檔**：`CHAR_AUDIO[字].r[粵拼]`，按上下文選正確讀音
  3. **逐字拼接**：`charAudio` 串行隊列（onended 續播、onerror 自動跳過缺檔），任意文字都讀得出
  4. **系統 TTS**：只在真的偵測到粵語音色時當補充；用戶亦可在「我的」手動開「優先系統語音」
  - `chSpans(el, text, py)` 新增第三個參數，逐字寫入 `data-jp`，令「銀行」的行讀 hong4、「行街」的行讀 haang4。
  - 劃選朗讀上限 `MAX_SPEAK = 24` 字。
- **「我的」頁發音引擎卡**：狀態點 + 本地字庫數 + 音檔數 + 系統音色狀態 + 「重新檢測」/「優先系統語音」開關 + **按平台自動展開**的安裝引導（iOS/Android/Windows/macOS，用 UA 判斷＋標「你而家呢部機」）。無音色時文案改為「唔影響點讀，App 用自己嘅本地錄音出聲」。
- **新增體檢工具** `tools/verify_audio.py`：檢查字庫/課程音檔完整性、空殼檔、並**模擬前端路由算課程覆蓋率**。
- **驗證結果**：1105/1105 生成成功、0 失敗；逐字覆蓋 **3264/3264（100%）**、整句 **606/606** 全部可由本地音檔拼出；課程錄音 636/636 齊。
